# Задача 2
## Выбор и настройка мониторинга в системе

### Мотивация
Для поиска узких мест и определения проблем работы сервисов при текущей архитектуре нужно внедрить решения по мониторингу.
Также мониторинг упростить переход на Kubernetes в будущем и позволить определить достигнутые результаты: что улучшилось, а что нет

### Выбор подхода к мониторингу
- Для бэкэнда (ShopApi, CrmApi, MesApi) и брокера (RabbitMQ) подойдет подходы "USE" и "Четыре золотых сигнала от Google" для определения того,
как серверы справляются с нагрузкой и большим трафиком
- Для взаимодействия с пользователями подойдёт подход "RED", он позволит частоту запросов и ошибок, а также время 
выполнения запроса

### Метрики
- RabbitMQ
  - Number of dead-letter-exchange letters in RabbitMQ
    - Позволит отследить, когда сервисы не смогли обработать сообщение из брокера
    - Ярлык: rabbit-dle
  - Number of requests (RPS) for internet Shop API
    - Частота запросов к Shop API для анализа
    - Ярлык: rabbit-shop-api-rps
  - Number of requests (RPS) for CRM API
    - Частота запросов к CRM API для анализа
    - Ярлык: rabbit-crm-api-rps
  - Number of requests (RPS) for MES API
    - Частота запросов к MES API для анализа
    - Ярлык: rabbit-mes-rps
  - Queue length for internet Shop API
    - Длина очереди к Shop API для анализа
    - Ярлык: rabbit-shop-api-queue-length
  - Queue length for CRM API
    - Длина очереди к CRM API для анализа
    - Ярлык: rabbit-crm-api-queue-length
  - Queue length for MES API
    - Длина очереди к MES API для анализа
    - Ярлык: rabbit-mes-queue-length
  - CPU % for RabbitMQ
    - При высокой загрузке возможна потеря сообщений брокером
    - Ярлык: rabbit-cpu-usage
  - Memory Utilisation for RabbitMQ
    - При не хватке памяти возможна потеря сообщений брокером
    - Ярлык: rabbit-mem-usage
- CRM API / Shop API / MES
  - CPU %
    - Загрузка CPU
    - Ярлык: $serviceName-cpu-usage
  - CPU Load Average
    - Загрузка CPU на задачу
    - Ярлык: $serviceName-cpu-load-average
  - Memory Utilisation
    - Зарузка памяти
    - Ярлык: $serviceName-mem-usage
  - SWAP usage
    - Использование файла подкачки
    - Ярлык: $serviceName-swap-usage
  - Response time (latency)
    - Задержка ответа
    - Ярлык: $serviceName-response-latency
  - Number of HTTP 200
    - Количество успешных ответов
  - % of HTTP 200
    - Процент успешных ответов
    - Ярлык: $serviceName-response-success-pct
  - Number of HTTP 500
    - Количество ошибок
  - % of HTTP 500
    - Процент ошибок
    - Ярлык: $serviceName-response-error-pct
  - Kb tranferred (received)
    - Исходящий трафик. Для анализа и контроля бюджета на защиту от DDOS
  - Kb provided (sent)
    - Входящий трафик. Для анализа и контроля бюджета на защиту от DDOS
- БД
  - CPU %
    - Загрузка CPU
    - Ярлык $serviceName-db-cpu-usage
  - Memory Utilisation
    - Зарузка памяти
    - Ярлык $serviceName-db-mem-usage
  - SWAP usage
    - Использование файла подкачки
    - Ярлык $serviceName-db-swap-usage
  - Disk Utilisation
    - Занятое дисковое пространство. Для контроля и расширения при необходимости
    - Ярлык $serviceName-db-disk-usage

### План действий
1. Установить Prometheus, настроить сбор метрик
2. Установить Grafana, настроить дашборды
   - Трафик (для каждого сервиса)
   - CPU Usage (для каждого сервиса и бд)
   - Mem Usage (для каждого сервиса и бд)
   - Длина очереди RabbitMQ (для каждого сервиса и бд)
   - Disk Usage (для каждой БД)
   - Трафик (для каждого сервиса) / частота ошибок
   - Трафик (для каждого сервиса) / длина очереди
   - CPU Usage (для каждого сервиса и бд) / частота ошибок
   - Mem Usage (для каждого сервиса и бд) / частота ошибок
3. Добавить алерты на основе метрик
